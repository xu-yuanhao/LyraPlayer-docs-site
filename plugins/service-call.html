服务消息调用 ​

LYRA_INTERFACE_SERVICE_CALL（28，plugin/service_call_contracts.h）是宿主帧线程上的同步类型化端点分发：按服务句柄和消息接口 ID 调用任意已选中服务，不需要该服务的私有符号。

结构 ​

LyraServiceCallV3 只有 size/version/user/request。C++ 调用方使用内联助手 lyra_service_call(api, handle, interface_id, message, reply) 构造信封，不必手写协议胶水。

  • HANDLE：注册表中的活动能力句柄；
  • INTERFACE：已分配的消息接口 ID；
  • MESSAGE：恰好 sizeof(LyraMessageV3) 的字节，先复制再校验。

分发会在 query 与 request 期间建立目标所有权、阻止活跃实现被卸载，并校验 reply。冻结（非消息）接口不会被重新解释为消息端点。

信封语义 ​

MESSAGE 的字段表与数据只在本次调用期间借用——这不是线格式或文件格式，不能序列化、落盘或延迟执行。嵌套 MESSAGE 只用于本进程同步调用。返回字段借用到下一次调用前，插件须立即复制需要的数据。

适用场景 ​

  • 插件互相调用：拿到对方服务句柄后按接口 ID 发消息；
  • 宿主端点调用：对 system.* 等内置服务做类型化请求；
  • 自定义服务间编排：不走 capability 名字分支。

约束 ​

  • 帧线程同步调用；不要在音频回调或工作线程里调用；
  • size==sizeof、version、句柄有效性都严格校验，失败返回 LYRA_MESSAGE_INVALID；
  • 调用是同步的——目标服务慢会阻塞帧线程，耗时工作应放在对方的异步接口里。
