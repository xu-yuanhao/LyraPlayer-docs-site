# 安全与信任边界

原生 `.so` 在应用进程内运行，可调用系统能力、读应用可读的数据，也可能崩溃整个播放器。目录签名与包摘要保证来源和字节完整，不提供权限沙箱或恶意代码审计。

## 三种校验

| 校验 | 保护什么 |
| --- | --- |
| APK 永久签名 | Android 应用升级身份 |
| 插件目录 ECDSA 签名 | 可信发布者提供的索引内容 |
| 包 SHA-256 + ZIP/ELF 检查 | 下载字节、导入路径、平台与 ABI |

目录使用 P-256、SHA256withECDSA；index.sig 为 DER 签名原始字节，公钥是 Base64 SPKI DER。签名对象是 index.json 的实际字节，不是 JSON 解析后的等价对象。格式化索引后必须重签。

缓存也重新验签。HTTPS、有界重定向/读入和超时保护网络过程。签名失败保留已验证旧列表，不使用未验证新包。信任组的镜像共用一个公钥。

## 密钥

APK JKS 与目录签名私钥用途不同。私钥只在维护者本机私有路径，不提交、不嵌入 APK、不写进文档或 CI 日志。发布者保留备份和密钥轮换计划；更换公钥意味着变更用户信任配置，不能仅在镜像换签名后期待旧客户端接受。

## 安装与更新

本地同 ID 导入拒绝覆盖；市场更新先在私有 staging 完整校验，原子替换并保留失败恢复路径。卸载不删用户配置，加载器等线程安全退出才释放代码。

许可证、作者声明与签名来源各自独立：有合法许可证不意味着用户应该信任代码，有签名也不证明元数据里的许可证正确。
