# 插件测试与验收

核对插件库导出、ZIP 内容和实际设备上的加载、替换与卸载。

## 编译与包检查

```sh
bash examples/build.sh
```

脚本编译 C 示例为 AArch64 ELF，检查导出入口并生成 ZIP。网站仓库的 `npm run check` 还检查公开参考覆盖、SDK 一致性、内部链接、源码泄露边界与示例 C 语法。

自己的包检查清单：manifest 与入口 ID/能力一致；ABI 3；entry 是同级文件名；ZIP 没有越界路径；图标/说明与实际许可证一致；平台和架构匹配设备。

## 集成场景

| 类别 | 验收 |
| --- | --- |
| 所有插件 | 安装、活动状态、错误回退、卸载、重启 |
| UI | 点击与拖动、窗口变化、切歌、暂停、返回、连续操作 |
| 参数 | 默认值、错误类型、界限、写入下一帧可见、重启持久化 |
| 模式 | 空/单首队列、首尾边界、手动与自动、真实顺序一致 |
| 播放 | seek、锁屏、长后台、音频焦点、设备路由、提供者退出 |
| 数据 | revision 变化、旧结果拒绝、UTF-8 长字符串、无歌词 |
| 网络 | 超时、坏签名、坏摘要、旧缓存、镜像失败、取消 |

不要在稳定帧反复分配大缓冲，不在音频实时回调做网络或磁盘操作。quiesce 必须等待线程真正退出，不用固定延时伪装。

## 反馈

记录宿主版本、SDK ABI、插件版本、设备系统/架构、复现动作、实际结果、期望结果和错误日志。不要提交用户歌词正文、私钥或签名密码。静音/mock 测试不能证明音频质量，编译通过不能证明 UI 观感。

日志获取与恢复限制见[排错](/plugins/troubleshooting)。
